# 入职周年提醒修复 v1.0.0

发布日期：2026-09-21
版本标识：anniversary-fix-v1.0.0
功能完成由用户确认，并授权从 test 合并到 main。

## 背景

“入职周年提醒”（功能三）在 offer-monitor-v1.0.0 里就已经存在，但一直没有被真实
触发过。这次首次真实测试暴露出四个连续的问题，逐一定位修复：

1. `parse_anniversary_fields` 只认独立的“编制组织：/部门：”字段行，但云昭机器人
   的真实分组提醒消息是紧凑格式“花名（编号｜编制组织/部门）”——跟已验证过的
   今日转正触发格式同源。加了紧凑格式的回退解析。
2. “技术/效能部”全员群的路由关键词（技术部/效能部/技术效能部）没有覆盖真实花
   名册里技术中心员工实际使用的部门名“研发部”，加了“技术中心”“研发部”两个
   关键词。
3. `names_from_anniversary_trigger` 同理只认“花名：”字段或跟入职信息文件里已知
   花名反查，两者都可能因为紧凑格式或信息文件还没更新而失配；加了直接从紧凑
   格式取花名前缀的最终回退。
4. `anniversary.py` 的 `_download_text` 一直在用 `response.text`（依赖 requests
   自己猜的编码），跟 `regularization.py` 早就修过的同一个 Latin-1 乱码坑一样，
   导致周年祝贺语文件内容读出来是乱码、花名怎么都匹配不上正文。改成直接按
   UTF-8 字节解码，和 regularization.py 保持一致。

同时按用户要求：SSC 审核通过（测试3/3）、海报和祝贺语转发到全员群后，自动删除
收藏夹里的那条草稿（复用今日转正功能里已有的 `delete_draft_after_send` 机制）。

## 验证

- 花名/部门解析用真实的“今日转正”触发格式和真实周年祝贺语.txt 内容核对过。
- 新增测试专门验证：`response.text` 若真的按错误编码解码会得到乱码（反面对照），
  证明编码修复不是巧合命中。
- 新增测试验证测试3审批通过后收藏夹草稿被正确删除。
- 全仓库 106 项测试通过，Python 编译通过。
